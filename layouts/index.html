AREAS OF EXPERTISE / THE WORK I DO

Infrastructure and software, together.

Background and technical stack ↗

Cloud engineering is not separate from software delivery. I work across the layers where infrastructure, applications, permissions and operational behaviour meet. Each discipline below connects to work you can inspect.

01Platform engineering

Internal engineering workflows, service boundaries, GitOps delivery and infrastructure-facing APIs. I focus on reducing repeated manual operations without introducing an opaque control plane.

Warden: policy-bound automation ↗
02DevOps and release engineering

CI/CD, containers, GitHub Actions, Argo CD, deployment health checks and rollback/recovery considerations. A successful build is not the same thing as a verified release.

Inspect this site's delivery workflow ↗
03Cloud engineering and infrastructure as code

AWS networking, IAM and resource configuration, Terraform, short-lived credentials and drift investigation. I prefer reproducible changes that can be reviewed before they reach a live environment.

DriftGuard: live state versus desired state ↗
04Backend and software engineering

Python, FastAPI, PostgreSQL, APIs, tests and services that expose infrastructure state safely. The software must handle failed dependencies, retries, identities and incomplete results explicitly.

Review the backend implementation ↗
05Kubernetes and infrastructure security

Kubernetes deployment configuration, GitOps reconciliation, RBAC, container scanning, runtime signals and policy controls. Finding an issue and authorizing its remediation are different security boundaries.

SENTINEL: security posture investigation ↗
06Observability and operational reliability

Metrics, logs, traces, failure investigation and post-deployment verification. I treat monitoring as evidence for decisions, not proof that a system is fault-tolerant.

Read my observability research ↗
07Execution safety and AI infrastructure research

Execution identity, recovery contracts and controls around automated infrastructure changes. These are active research and implementation areas, not claims of deployed autonomous production systems.

CER: execution safety research ↗
