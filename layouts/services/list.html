ENGAGEMENT MODEL

Define the problem before the implementation.

  1. Scope. Review the current architecture, constraints and failure symptoms.
  2. Agree evidence. Define a deliverable and observable acceptance criteria.
  3. Implement. Make targeted changes with reviewable source and configuration.
  4. Verify. Record test results, operational handover and remaining limitations.

HOW WORK IS EVALUATED

How I approach a contract.

Inspect a public delivery example ↗

The public delivery example covers this website, not a customer's system. For each new engagement, I agree on access, review and acceptance criteria before implementation.

01 / BOUNDARY

Agree what can be accessed and disclosed.

Establish systems, permissions, confidential information, review authority and what evidence can leave the environment.

02 / DELIVERY

Make changes reviewable.

Specify the change, known failure modes, test approach and approval requirements before implementation where the contract permits.

03 / VERIFICATION

Record what passed—and what was not tested.

Use agreed acceptance checks, release signals and a handoff that distinguishes observed behaviour from unverified assumptions.
